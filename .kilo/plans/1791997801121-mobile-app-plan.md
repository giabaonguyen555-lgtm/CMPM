# Kế hoạch hoàn thiện Frontend Web — Hanoi Heritage Audio Guide

## Phạm vi và nguyên tắc
- Hoàn thiện React.js Web trên desktop và mobile browser; chưa triển khai React Native app và CI/CD production.
- Giữ nguyên Clean White & Charcoal Editorial: nền trắng, slate/charcoal, border mảnh, card bo góc, accent đen, category color nhẹ.
- Không thay đổi business concept hoặc tự thêm backend giả; các API chưa có được bọc bằng mock service rõ ràng và gắn nhãn demo.
- Không làm public shell (Header/Footer/Mini Player/ChatWidget) ảnh hưởng Admin route.

## 1. Baseline và chất lượng nền
1. Tạo route `404` và `ErrorBoundary` để lỗi component không làm trắng toàn app.
2. Chuẩn hóa các trạng thái dùng chung: loading skeleton, empty state, error state, retry, toast.
3. Tách design tokens và các UI primitives tối thiểu: Button, Badge, Card, Modal, Tabs, PageHeader, StatusBadge.
4. Rà soát duplicate class và spacing giữa Explore, Location, Map, Favorites, About, Auth, Paywall, Admin.
5. Giữ backup trước các refactor page lớn; chạy regression sau từng nhóm thay đổi.

## 2. Audio UX production-ready ở frontend
1. Giữ audio language độc lập với UI language; Header đổi toàn UI, Audio selector chỉ đổi narration/transcript.
2. Chuẩn hóa `AudioPlayerContext`: idle/loading/playing/paused/ended/error, currentTime/duration, cleanup callback, retry.
3. Sửa listened session: không tăng khi pause/resume; chỉ ghi nhận một phiên ổn định theo POI/session.
4. Hoàn thiện Audio Guide và Mini Player: loading, lỗi, blocked playback, retry, close, language switch, responsive mobile, không che footer/content.
5. Chuẩn bị data contract `audio`/audio theo ngôn ngữ nhưng không giả định đã có file thật; fallback TTS được hiển thị rõ.
6. Test các case: đổi ngôn ngữ khi đang phát, seek/skip, đóng player, audio lỗi, Speech API không hỗ trợ.

## 3. Map, GPS và mobile-browser UX
1. Giữ search/filter, scroll zoom, marker và stacking header hiện có; không để map chiếm scroll toàn trang.
2. Làm selected POI rõ trên sidebar và marker; phân biệt POI thường, selected, nearest, user location.
3. Gom controls thành nhóm rõ: location, audio discovery, route; thêm reset filter và empty state.
4. Hoàn thiện GPS permission/loading/error/retry; hiển thị khoảng cách và nearest state dễ quét.
5. Auto-play chỉ opt-in, có bán kính, cooldown, chống lặp và trạng thái tắt; không tự xin location khi vào trang.
6. Mobile layout: map cao vừa viewport, POI list cuộn riêng/bottom-sheet-like, controls không che map.
7. Gắn nhãn route hiện tại là visual preview; không gọi là directions nếu chưa có routing API.

## 4. Auth và Paywall demo rõ ràng
1. Auth UI: password visibility, confirm password, validation/error, loading, logout, session state, redirect `next`.
2. Không lưu password; giữ auth demo rõ ràng là client-only.
3. Bảo vệ Favorites/Paywall/Admin theo phạm vi đã chốt; Admin mock có thể mở tự do hoặc chuyển role guard sau này.
4. Paywall: chỉ chặn tính năng premium đã định (GPS audio/proximity/route nâng cao); Audio Guide cơ bản vẫn miễn phí nếu đó là rule sản phẩm.
5. Hoàn thiện mock Online/Cash: pending/success/error, retry, claim code, quay lại tính năng ban đầu qua `next`.
6. Không mô phỏng API production dưới dạng “đã thanh toán thật”; hiển thị Demo mode/status.

## 5. Chatbot UI mock hoàn chỉnh
1. Thêm loading/typing, error/retry, clear conversation và scroll tới message mới.
2. Giữ POI card/image/link trong response; không tuyên bố RAG/AI backend khi chưa có API.
3. Kiểm tra vị trí widget với Mini Player, Map controls, mobile safe-area và keyboard.
4. Tách `chatService` interface để sau này thay mock bằng API mà không đổi layout.

## 6. Admin UI hoàn thiện ở mức frontend mock
1. Giữ route `/admin` tách khỏi Header/Footer/Player/ChatWidget public.
2. Overview, Payments, POI Library, Monitoring dùng URL query tab và responsive layout.
3. Bổ sung modal Add/Edit POI, form đa ngôn ngữ, modal Confirm cash payment, toast success/error; action mock phải có phản hồi, không để nút chết.
4. Payment table có amount/date/method/status/claim code, filter, empty state, mobile card fallback.
5. POI library có search, empty state, status fallback, alt text, responsive action layout.
6. Monitoring gắn nhãn mock/last updated; không trình bày số hard-code như live production.
7. Sau này role guard/API thật chỉ là adapter, không đổi design.

## 7. Accessibility và responsive QA
1. Keyboard test cho header dropdown, modal, tabs, chatbot, player và form.
2. Bổ sung `aria-expanded`, `aria-controls`, tab semantics, focus trap modal, accessible icon labels.
3. Kiểm tra contrast category/status, alt ảnh, reduced motion và text scaling.
4. Test viewport 320, 375, 414, tablet, 1366 và màn hình lớn.
5. Test Chrome, Edge, Firefox và Safari nếu có môi trường.
6. Kiểm tra không bị che bởi sticky player, chat widget, footer hoặc map overlays.

## 8. Performance và test FE
1. Lazy-load route nặng: Map, Admin, About; tách Leaflet/Admin bundle bằng dynamic import.
2. Lazy-load card images, xử lý ảnh lỗi/placeholder, audit kích thước ảnh hero.
3. Thêm unit tests cho distance, favorites, audio state, auth state, payment mock và translation fallback.
4. Thêm component tests cho Search, dropdown, Audio Guide, Mini Player, Map controls, Paywall, ChatWidget, Admin tabs.
5. Thêm E2E smoke flows: Explore → Location → audio; Map → GPS; Login → Favorites; Paywall demo; Admin tabs.
6. Thêm script kiểm tra thống nhất (`test`, `build`, lint/format check nếu cấu hình được); không thực hiện CI/CD trong phạm vi này.

## Thứ tự triển khai
1. Baseline/ErrorBoundary/UI primitives.
2. Audio UX và regression.
3. Map/GPS mobile-browser UX.
4. Auth/Paywall demo.
5. Chatbot states.
6. Admin modal/actions/responsive.
7. Accessibility/responsive QA.
8. Performance và test FE.

## Tiêu chí hoàn thành
- Không có màn hình trắng khi component/runtime lỗi; có ErrorBoundary/404.
- Mọi nút hiển thị đều có hành vi, trạng thái disabled/loading hoặc ghi rõ Demo.
- Audio, Map/GPS, Paywall, Chatbot và Admin có loading/error/empty/retry phù hợp.
- Header/Footer/Mini Player/ChatWidget không che nội dung trên desktop/mobile browser.
- Giao diện vẫn cùng Clean White & Charcoal Editorial, không redesign toàn bộ.
- `npm test` và `npm run build` pass; cảnh báo bundle được giảm hoặc có lý do được ghi nhận.
- Mobile React Native và CI/CD production được giữ ngoài phạm vi kế hoạch này.
